# CSM Skills

**58 plug-and-play agent skills for Customer Success Managers. Works from a single conversation. Scales to a production system.**

Each skill works in isolation -- pick the one you need, upload it to any [Agent Skills](https://agentskills.io)-compatible platform (Claude, Codex, or equivalent), and get value immediately. Use them standalone from manual input. Use them repeatedly for persistent account management. Or wire them into your data systems for fully automated operation. The skills are the same at every level -- the input method is what changes.

## Why This Exists

Most CSM tooling requires a system implementation before it delivers value. These skills deliver value the moment you use them. They work from what you already know about your accounts, typed into a conversation with an agent. But that is the floor, not the ceiling. The same skill that works from a CSM's typed notes today works from a CRM data feed tomorrow -- without modification.

This is the starting point for CSMs who want to work with agents regardless of where they are in their tooling maturity. Use these standalone. Use them as the persistent backbone of how you manage your book. Or use them as the entry point to the [CSM Agent Skills](https://github.com/stephenrogan/augmented-csm) architecture when you are ready for the full system-level approach.

## How to Use

### On Claude (claude.ai)
1. Download the skill folder (or the zip of all skills)
2. Go to Settings > Features > Skills
3. Upload the skill folder as a zip
4. Start a conversation -- the skill activates when your prompt matches its description

### On Claude Code
1. Place the skill folder in your `.claude/skills/` directory
2. The skill is automatically available

### On Codex
1. Place the skill folder in your `.codex/skills/` directory
2. The skill is automatically available

### Without a Skills Platform
Every skill is a markdown file. You can read the SKILL.md and use it as a structured prompt in any AI assistant. The skill format is a convenience, not a requirement.

## How These Skills Scale

Each skill operates at whatever level of maturity your environment supports. The skill logic, frameworks, and output structures are the same at every level. What changes is how data gets in.

### Level 1: Manual (Day One)

You type what you know. The skill structures it.

A CSM opens a conversation, provides account context from memory or a quick CRM glance, and gets a structured output -- a health assessment, a pre-call brief, a save play, a prioritised book. No integrations, no pipelines, no setup. Value in 5 minutes.

**This is the floor.** Every skill in this repo works at this level with nothing but a keyboard.

### Level 2: Persistent (Week Two)

You use the same skill repeatedly for the same accounts. Context accumulates.

"Here is the updated health assessment for Acme -- last time we scored them 68, engagement was declining. Here is what changed since then." The CSM brings the continuity. The skill provides the structure. Over time, the skill becomes the operating rhythm for how you manage your accounts -- a consistent framework applied to every interaction, every assessment, every plan.

**No modification needed.** The skills work for persistent use as-is. The CSM is the memory layer.

### Level 3: Data-Connected (Month Two)

You paste in data from your systems. Spreadsheet exports, CRM reports, analytics dashboards.

Instead of answering "how actively is the customer using the product?" from memory, you paste the usage data. The health assessment becomes data-driven instead of judgment-driven. The pre-call prep brief pulls from real activity logs instead of recollection. The accuracy increases, the CSM's effort decreases, and the output quality compounds.

**Still no integration required.** Copy-paste from your existing tools is enough.

### Level 4: Integrated (Quarter Two)

You wire the skill into your data sources. CRM APIs, product analytics, calendar, support platform.

The skill now pulls data automatically. The manual-health-assessment becomes the automated bi-health-score from the [system architecture](https://github.com/stephenrogan/augmented-csm). The pre-call-prep becomes the bi-account-brief that triggers before every scheduled meeting. The process-audit-worksheet becomes the foundation for your agent-augmented operating model.

**The skill logic does not change.** The assessment framework, the scoring model, the output structure -- all identical. The only difference is that a machine provides the input instead of a human. The upgrade path is: swap the input method, keep everything else.

### The Point

These skills are not "lightweight tools for people who cannot afford real systems." They are the same frameworks, the same thinking, and the same structure that power a production agent-augmented CS operation. Manual input is an accessibility feature, not a limitation. It means you start getting value today, and the value only increases as your environment matures.

## Design Principles

**Works at every level.** From a single CSM typing notes to a 50-person CS org with full data integration. The skill adapts to the input it receives.

**Zero required dependencies.** No skill requires another skill, a CRM integration, or a product analytics pipeline to function. Dependencies are optional enhancements, not prerequisites.

**Immediate value.** Every skill delivers a useful output in a single session. No setup, no configuration, no multi-step onboarding before you see results.

**Structured thinking, not just structured output.** The skills do not just format your input prettily. They impose assessment frameworks, scoring models, and decision logic that improve the quality of the CSM's thinking -- whether the input comes from memory or from a data warehouse.

**Opinionated.** These skills take positions on what good CS looks like. They encode senior operator judgment into reusable frameworks. If you disagree with a position, fork the skill and adapt it.

## Relationship to CSM Agent Skills

This repo contains **standalone tools** -- individual skills that work independently at any maturity level.

The [Augmented CSM](https://github.com/stephenrogan/augmented-csm) repo contains **a system architecture** -- 38 interdependent skills that form a complete agent-augmented CS operating model.

They are not competing approaches. They are stages of the same journey:

1. **Start here.** Pick a standalone skill, use it manually, see the value of structured thinking with agent support
2. **Build the habit.** Use the skills persistently across your book. They become your operating rhythm
3. **Connect data.** Start feeding system data into the skills. Outputs get more accurate, CSM effort drops
4. **Go system.** When you are ready to wire skills together into an integrated architecture, the system repo is the blueprint. The standalone skills you have been using are the same frameworks, now automated
